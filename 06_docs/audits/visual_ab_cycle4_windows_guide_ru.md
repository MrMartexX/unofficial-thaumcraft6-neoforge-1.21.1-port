# Thaumcraft Visual A/B Harness — Cycle 4, снимки окружения и планы видео

Дата: 05.11.2026. Статус: **локальная реализация, Windows-клиент ещё не подтвердил эту поставку**.

Cycle 4 построен поверх Cycle 3. Не меняет Minecraft, игровые миры, `options.txt`, моды, исходные F2/видео или файлы настроек. Игровые результаты остаются `NOT_RUN`.

## Что добавлено

- `environment/inspect.ps1`: только чтение разрешённых параметров `options.txt` у **обоих** клиентов, списка имён JAR в `mods`, имён ресурс-паков и шейдер-паков. Все файлы снимка сохраняются в `RUN_.../environment.json` (локально).
- Отпечатки модов/паков вычисляются **по именам файлов**, не по содержимому JAR/ZIP. Проверка `verify` также сверяет SHA-256 самого `options.txt` и отпечаток пути игрового каталога; она не подтверждает целостность модов по байтам.
- Отдельно отмечаются сырые несовпадения FOV, gamma, GUI Scale, дальности прорисовки, FPS и других выбранных параметров. **Совпавшие сырые значения не доказывают совпадение картинки**. Состояние всегда `CALIBRATION_REQUIRED`, пока человек не выполнит проверку G00 по протоколу.
- `video/plan.ps1`: ручная привязка двух **уже индексированных** записей одной сцены (`legacy` и `modern`) с независимыми стартовыми секундами и общей продолжительностью. Отдельные видео проверяются по SHA-256. План не декодирует, не перемещает и не обрезает видео.
- `reporting/report.ps1`: экспортирует только число снимков окружения и число планов видео. Исходные пути, содержимое опций, имена модов/паков, `environment.json`, `video-plans.json`, `media.json`, логи и видео **не включаются**.
- Меню `session/controller.ps1` дополнено `E` (окружение) и `T` (план сегментов), а меню `M` показывает безопасные ID видео для выбора пары.

## Один объединённый офлайн-прогон (позже, без запуска Minecraft)

Когда понадобится проверить новую версию в изолированном рабочем дереве:

```powershell
git -C D:\TC6_AB_Cycle1 status --short
git -C D:\TC6_AB_Cycle1 fetch origin codex/visual-ab-cycle4-calibration-20261105
git -C D:\TC6_AB_Cycle1 switch --detach origin/codex/visual-ab-cycle4-calibration-20261105
pwsh -NoProfile -File D:\TC6_AB_Cycle1\tools\visual-ab\tests\validate-offline.ps1
```

Перед переключением `switch --detach` убедиться, что `status --short` пуст: не перезаписывать собственные несохранённые изменения.

Встроенные тесты создают временные **синтетические** игровые каталоги, `options.txt`, пустышки JAR/MP4 и PNG. Они должны подтвердить неизменность исходных медиа, хеши, отказ от неверных видео ID, детектирование подмены, честный `NOT_RUN` и отсутствие приватных файлов в ZIP. Это не клиентское испытание и не проверка настоящих видеокадров.

## Использование на сохранённом RUN

```powershell
$Ab = 'D:\TC6_AB_Cycle1\tools\visual-ab'
$Run = 'D:\TC6_AB_Evidence\RUN_20261104T202107Z_5153ed72'
$Config = 'D:\TC6_AB_Cycle1\tools\reports\local\visual-ab\config.local.json'

# Снимок обоих клиентов: только чтение игровых каталогов.
pwsh -NoProfile -File "$Ab\environment\inspect.ps1" -Action capture -RunPath $Run -ConfigPath $Config
pwsh -NoProfile -File "$Ab\environment\inspect.ps1" -Action status -RunPath $Run
pwsh -NoProfile -File "$Ab\environment\inspect.ps1" -Action verify -RunPath $Run -ConfigPath $Config

# Сначала через M в контроллере узнайте ID отдельно индексированных legacy и modern видео.
pwsh -NoProfile -File "$Ab\video\plan.ps1" -Action status -RunPath $Run
pwsh -NoProfile -File "$Ab\video\plan.ps1" -Action plan -RunPath $Run `
    -LegacyVideoId 'VIDEO_ID_LEGACY' -ModernVideoId 'VIDEO_ID_MODERN' `
    -LegacyStartSeconds 2.5 -ModernStartSeconds 3.25 -DurationSeconds 6
pwsh -NoProfile -File "$Ab\video\plan.ps1" -Action verify -RunPath $Run
```

`E` в контроллере предлагает снять снимок, проверить его или посмотреть статус. `T` позволяет задать вручную времена для пары видео, либо проверить их SHA-256. Отсутствие видеозаписей не является ошибкой для сессии, которая ещё не перешла к динамическим сценариям: просто не создавайте фиктивный план.

## Честные границы

1. Снимок `options.txt` отражает **файлы на диске**, а не обязательное состояние запущенного Minecraft. Java, версия загрузчика, камера, реальное разрешение F2, порядок активных ресурс-паков и точная сборка порта всё ещё требуют клиентского подтверждения.
2. Разница исходных значений (например, FOV `0.0` или gamma `0.5`) **не конвертируется автоматически** между версиями. GUI Scale нужно сверять в реальных пикселях, camera yaw/pitch — по F3 в каждом клиенте.
3. Видеоплан хранит пользовательские смещения в секундах, но не проверяет длительность записи или общий момент эффекта. Нет `ffprobe`/`ffmpeg`, синхронизации кадров, подтверждённого наложения и сравнения анимаций.
4. Для предыдущего `G00.W-05.BASELINE.OVERVIEW` сохранены оригинальные два F2; они проверяют работу транспорта доказательств, но не дают визуальный `PASS`.
5. Новые данные находятся только внутри выбранного RUN вне Git. В общий ZIP идут лишь агрегированные счётчики. Для публикации подробных журналов или локальных снимков требуется отдельное решение и проверка приватности.

## Следующий технический шаг

Реальный Windows-прогон одного объединённого офлайн-теста; затем ручная проверка окружения клиента и при необходимости установка/проверка `ffprobe` для получения длительности записей. После этого можно проектировать детерминированную нарезку двух источников и покадровое сопоставление, не присваивая результатам автоматически `PASS`.
