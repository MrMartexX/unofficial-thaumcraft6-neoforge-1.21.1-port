# V0 client FX / animation semantic diff, first focused batch (2026-11-03)

> **Source-only comparison.** Pinned original snapshot and NeoForge port to `main` `72eaac17a1e1c0c51b27cb151ef7f244944c89d5`; draft review branch is separate. The findings below are not a claim of in-game equivalence or a regression-test pass.

## Scope and method

Compared legacy `FXBeamWand`, `FXBeamBore`, `FXArc`, `FXBolt`, `FXEssentiaStream`, `FXDispatcher`, `ParticleEngine`, `RenderArcaneBore`, `EntityArcaneBore`, `PacketFXBoreDig`, `PacketFXWispZap`, `TileNitor`, `EntityBottleTaint`, `ModelTaintSeed` and `RenderTaintSeed` to current `TCFXDispatcher`, `TCInfusionClientEffects`, `TCLegacyParticleEngine`, `TCWispClientEffects`, `TCNitorClientEffects`, `TCArcaneBoreRenderer`, `TCArcaneBoreEntity`, `TCBottleTaintEntity`, `TCTaintSeedRenderer`, `TCTaintacleRenderer` and `TCClientEvents`. Used repository-wide indexed code searches to cross-check old beam/arc dispatcher names against port files. That search is supporting evidence, not proof against any independently named implementation.

## Source-semantic findings, prioritised

| Priority | Feature | Original 1.12.2 semantics | Port 1.21.1 semantics | Source-level classification |
| --- | --- | --- | --- | --- |
| **P0 (visual)** | Active Arcane Bore beam | `RenderArcaneBore.doRender` checks `clientDigging`, binds `textures/misc/beam1.png`, and emits beam quads alongside the model. `EntityArcaneBore` also sends `PacketFXBoreDig` for a timed dig burst. | `TCArcaneBoreRenderer.render` draws the textured device parts only; no beam quads or digging branch. `TCArcaneBoreEntity` exposes a server-side `digTarget` but the inspected renderer does not read it. Block break currently emits vanilla level event 2001. | **Confirmed source-level beam implementation gap in the inspected active renderer**, not yet runtime proof of no other beam effect. |
| **P1** | Taint bottle impact | `EntityBottleTaint.handleStatusUpdate(3)` loops **100** times through custom `taintsplosionFX`, then `bottleTaintBreak` adds 8 item-break particles and a splash-potion breaking sound. | `TCBottleTaintEntity.handleEntityEvent(3)` emits **24 item + 24 mycelium** particles with different motion and no explicit break sound in that handler. | **Confirmed visual recipe substitution**; functional infection/goo logic is separate and not in scope. |
| **P2** | Nitor core phase | `TileNitor.update` calls flames each tick and `if (count++ % 10 == 0)` makes core on first tick, then every 10. | `TCNitorBlockEntity.clientTick` increments `count` first, then `TCNitorClientEffects.tick` uses `count % 10 == 0`. First core is tick **10**, subsequently every 10. | **Confirmed minor first-core timing shift**; flame/core sprite, lifetime and color logic largely follow original. |
| **P1 / review** | Taint seed shape and motion | `ModelTaintSeed` builds dynamic multi-segment organic tentacles and uses `ModelRendererTaintSeed.render` with elapsed-time input. | `TCTaintSeedRenderer.createLegacyFoundationModel` builds a few simple boxes/tendrils; `render` applies global sway and attack rotation. | **Approximate foundation geometry**, not source-equivalent shape/animation; pair screenshots and motion captures. |
| **P2 / review** | General wand continuous beams and electric arcs | Legacy dispatcher has `beamCont`, `beamBore`, `arcLightning`, `arcBolt`; `FXBeamWand`/`FXBeamBore` support endpoint updates, pulse, rotation and impact. | No same-name counterparts in `TCFXDispatcher`; wisp zap does have a dedicated modern `TCWispClientEffects` bolt. | **Coverage review needed** by feature/caller, not a global conclusion that every beam/arc is absent. |
| **Positive with test gate** | Wisp zap bolt | `PacketFXWispZap` resolves source+target, colors bolt by source aspect and spawns `FXBolt` with width 0.6 and lifetime 3 ticks. | `TCWispClientEffects.accept` resolves both entity IDs, derives aspect color and creates `ZapBolt` with width 0.6 and 3-tick lifetime, triggered by `TCEntityFXNetwork` from `TCWispEntity`. | **Semantic path strongly evidenced**, but geometry/noise/brightness and packet visibility remain unverified. |
| **Positive with test gate** | Infusion essentia stream | `FXEssentiaStream` keeps keyed source→destination streams, extends lifetime, uses gravity/drag, tapering radii and colored droplets. | `TCInfusionClientEffects` has keyed `EssentiaStream`, extension, drag, 8-sided tube vertices, taper and drop particles; stream packets are drained from `TCInfusionClientFXCache`. | **Dedicated animated path exists**; exact scale, interpolation, tint and render-state parity require capture. |
| **P2 / review** | Generic essentia trail API | Original `FXDispatcher.essentiaTrailFx` creates a moving `FXEssentiaStream`. | New `TCFXDispatcher.essentiaTrailFx` samples a straight line and spawns many generic particles; the infusion-specific `TCInfusionClientEffects` is a separate, richer implementation. | **Same method name, different rendering algorithm**; audit individual callers before relying on it for old behavior. |

## Acceptance batch and minimum evidence

1. **Bore beam:** Record one original and one port clip of active mining with identical field of view, time, texture pack and GPU settings; compare beam presence, source offset, width, UV scroll, orientation, targets, spark density and breaking events. If port lacks it, design server-authoritative synchronization for active dig state and target before implementing a client beam renderer.
2. **Taint bottle:** Record two impact clips and sound, compare tint, 108-vs-48 spawned-particle budget (100 custom + 8 item particles vs 24 item + 24 mycelium), scale/motion, decay and bottle break sound. Preserve existing server-side taint mechanics while repairing visuals if needed.
3. **Nitor:** Observe first 20 client ticks after placement and stable flame/core cadence; phase shift can be corrected independently only after desired original timing is confirmed.
4. **Seed/tentacles:** Capture idle, attacking, hurt and death at matched camera angle/lighting, compare silhouette, segment flex, textures and animation.
5. **Wisp and infusion:** Capture Wisp bolt travel and color by aspect and infusion stream from pedestal/jar at fixed partial tick/sync delay, including Fast vs Fancy particle settings and chunk unload/reload.
6. Run **one** client test batch after feature-level work, collecting screenshots/clips, logs and GL/shader warnings; defer build/CI/server tests until an implementation PR is prepared.
