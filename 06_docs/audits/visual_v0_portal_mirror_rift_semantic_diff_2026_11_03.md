### PV-04. Flux Rift: geometry is not equivalent to renderer registration

- Legacy [RenderFluxRift.java L47-112](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/02_existing_decompiled_repo/Thaumcraft-6-Source-Code-master/src/main/java/thaumcraft/client/renderers/entity/RenderFluxRift.java#L47-L112) performs **four** draw passes using `CoreGLE.glePolyCone` with tessellation 6; three halo passes use radii multipliers 1.25, 1.75, 2.25, with additive blending and reduced depth writes, and fourth is base radius. Wobble depends on `ticksExisted + partialTick` and `clamp(1 - stability/50, 0, 1.5)`; goggles alter depth testing during first pass.
- Current [TCFluxRiftRenderer.java L21-71](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/client/renderer/TCFluxRiftRenderer.java#L21-L71) draws one quad per adjacent point pair with `entityTranslucentEmissive`, fixed purple vertex color `(180,70,255,180)`, `FULL_BRIGHT`, width `max(widthA,widthB)*6+0.02`. The geometry is a ribbon, **not** a six-sided multi-pass tube.
- Legacy `EntityFluxRift` [`calcSteps` L408–438](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/02_existing_decompiled_repo/Thaumcraft-6-Source-Code-master/src/main/java/thaumcraft/common/entities/EntityFluxRift.java#L408-L438) and current [TCFluxRiftEntity.java L554-588](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/common/entities/TCFluxRiftEntity.java#L554-L588) both generate seeded point chains with `ceil(size/3)`, girth `size/300`, 0.2 steps and 0.1 end caps. This geometry similarity is a **positive**; render surfaces and animation remain different.
- Current [TCEntityRenderers.java L17-22](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/client/renderer/TCEntityRenderers.java#L17-L22) explicitly binds Flux Rift to the renderer and [TCFluxRiftEntity.java L46-54](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/common/entities/TCFluxRiftEntity.java#L46-L54) synchronizes seed, size, stability and collapse. `tickClientParticles` [TCFluxRiftEntity.java L367-385](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/common/entities/TCFluxRiftEntity.java#L367-L385) adds portal particles in unstable/collapsing states, but these do not reproduce the multi-pass tube.
- **Risk to investigate, not a confirmed defect:** [TCFluxRiftEntity.java L86-90](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/common/entities/TCFluxRiftEntity.java#L86-L90) only triggers geometry rebuild on size change/empty list; client seed updates arriving after first geometry creation could leave an old-shaped list until size changes. Compare seed+size updates on initial tracking, reconnect and spawn; legacy also rebuilds primarily on size changes, so do not assume regression without a runtime trace.
- **Acceptance:** same size/seed/stability in original and current, stable vs unstable vs collapsing, goggles on/off, camera close/side, partial-tick motion, transparency/depth interaction and visibility behind opaque blocks.

### GM-01. Hole expansion is a separate behavior gate

- Original [TileHole.java L51-81](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/02_existing_decompiled_repo/Thaumcraft-6-Source-Code-master/src/main/java/thaumcraft/common/tiles/misc/TileHole.java#L51-L81) creates the eight non-center cells in the plane perpendicular to `direction` (Y, Z or X), then propagates one additional hole along `direction.getOpposite()` when `count > 1`.
- Current [TCHoleBlockEntity.java L52-55](https://github.com/MrMartexX/unofficial-thaumcraft6-neoforge-1.21.1-port/blob/72eaac17a1e1c0c51b27cb151ef7f244944c89d5/05_neoforge_port/src/main/java/thaumcraft/common/tiles/misc/TCHoleBlockEntity.java#L52-L55) creates only the forward hole. This changes the resulting tunnel footprint. It also affects how many shaded surfaces are visible, but correcting the **gameplay** implementation should be a separate task reviewed before checking PV-01 screenshots. No gameplay code changed here.
