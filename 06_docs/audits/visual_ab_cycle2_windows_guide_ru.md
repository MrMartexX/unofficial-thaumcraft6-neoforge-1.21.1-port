## 3. Что будет после успешного теста

Мы подготовим ограниченный пилот без массовой проверки всех групп. Сначала зафиксируем реальные версии двух клиентов, их настройки и привязку порта к фактически собранному исходному коммиту. Затем проверим одну простую F2-сцену в каждой версии.

Контроллер поддерживает:

| Команда | Результат |
| --- | --- |
| `start` | Уникальная новая папка `RUN_...` и `session.json` |
| `select` | Активная карточка и сторона LEGACY/MODERN |
| `watch` | Ожидание **новых** F2 PNG, автоматическое копирование и запись SHA-256 |
| `capture` | Ручной импорт конкретного PNG, если снимок уже сделан |
| `status` | Состояние сессии и количество зарегистрированных файлов |
| `verify` | Повторная проверка целостности всех сохранённых файлов |

Вся работа с доказательствами будет находиться в отдельном каталоге результатов вне Git. Оригинальные F2-файлы Minecraft остаются без изменений. Видеозаписи, GUI для выбора сценариев и окончательное A/B-решение будут добавлены позже.

## 5. Управление через меню (новый этап цикла 2)

После прохождения **обновлённого** `validate-offline.ps1` можно открыть меню:

```powershell
pwsh -NoProfile -File D:\TC6_AB_Cycle1\tools\visual-ab\session\controller.ps1
```

В меню доступны создание/возобновление сессии, просмотр пяти подготовленных пилотных карточек, выбор стороны и сцены, наблюдение за новыми F2, ручной импорт скриншота, заметки, проверка количества файлов и SHA-256.

При создании сессии введи отдельный каталог результатов, например `D:\TC6_AB_Evidence`. Это только **пример пути**. Не нужно переносить туда игровые миры; контроллер создаст новую папку `RUN_...` для доказательств.

Статус `IMAGE_COUNTS_MET_REVIEW_PENDING` означает, что количество скриншотов соответствует минимуму, но **не** означает визуального соответствия. Для динамических сцен контроллер отдельно показывает, что видео или логи ещё не зарегистрированы.

Первая настоящая игровая проверка через меню будет согласована после успешного офлайн-теста. До этого Minecraft запускать не требуется.
