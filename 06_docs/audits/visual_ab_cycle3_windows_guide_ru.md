# Visual A/B Harness — Cycle 3 (предварительная поставка)

## Границы подтверждения

Cycle 3 добавляет автономный HTML-просмотр пары скриншотов, JSON/Markdown-отчёт, проверяемый ZIP-пакет, безопасный повторный импорт и локальный реестр дополнительных медиа.
Инструменты не меняют Minecraft, миров, исходных PNG или игровые настройки. Статусы игры всегда `NOT_RUN`, ревью `NOT_REVIEWED`.
Скриншоты G00 из предыдущего smoke подтверждают **транспорт F2**, но не визуальное соответствие: G00 требует отдельной калибровки и логов.

## Один объединённый офлайн-тест (без Minecraft)

В отдельном рабочем дереве, обновлённом до ветки Cycle 3:

```powershell
pwsh -NoProfile -File D:\TC6_AB_Cycle1\tools\visual-ab\tests\validate-offline.ps1
```

В конце должны появиться строки `PASS` для Cycle 1/2/3 и медиа, тесты злонамеренных ZIP, недостоверной полноты и приватности. Тесты используют временные **синтетические** изображения, журнал и байтовую имитацию видео (не декодируется).

## Работа с существующей сохранённой сессией

```powershell
$Run = 'D:\TC6_AB_Evidence\RUN_20261104T202107Z_5153ed72'
$Ab = 'D:\TC6_AB_Cycle1\tools\visual-ab'

pwsh -NoProfile -File "$Ab\comparison\compare.ps1" -RunPath $Run -SceneId 'G00.W-05.BASELINE.OVERVIEW'
pwsh -NoProfile -File "$Ab\reporting\report.ps1" -Action build -RunPath $Run
pwsh -NoProfile -File "$Ab\reporting\report.ps1" -Action export -RunPath $Run
```

HTML-файл из `htmlPath` открывается в обычном браузере локально. Он содержит обе PNG-копии внутри HTML, не использует внешние сервисы. Предусмотрены Side-by-side, Overlay и интерактивное Difference Image. При разных разрешениях сравнение пикселей отключается с пометкой `UNALIGNED_FRAMES`. Сравнивать такие кадры как равноценные нельзя.

Overlay использует один ползунок прозрачности порта поверх оригинала. Нижний ползунок в разделе Difference Image **не управляет Overlay**: он задаёт порог выделения отличающихся пикселей. Старые HTML-файлы не обновляются автоматически; новые версии создаются пунктом `C`.

В интерактивном `session/controller.ps1` также доступны пункты `C` (HTML-сравнение), `R` (создать отчёт и ZIP), `I` (проверка и необязательный импорт ZIP), `L` (копия лога), `V` (индексирование внешнего видео), `M` (сводка и SHA-256 по дополнительным медиа). Старые пункты `1`–`9`, `S`, `0` сохранены.

### Дополнительные медиа (локально; пользовательский тест не требуется прямо сейчас)

Можно привязать текущий `latest.log` или уже готовую видеозапись к **выбранной** сцене и стороне. Используйте пункты `L` / `V` контроллера или команды:

```powershell
# Сначала выберите сцену и сторону в контроллере (пункт 4).
pwsh -NoProfile -File "$Ab\media\media.ps1" -Action snapshot-log -RunPath $Run -LogPath 'D:\PATH_TO_GAME\logs\latest.log'
pwsh -NoProfile -File "$Ab\media\media.ps1" -Action index-video -RunPath $Run -VideoPath 'D:\PATH_TO_RECORDING\capture.mp4'
pwsh -NoProfile -File "$Ab\media\media.ps1" -Action status -RunPath $Run
pwsh -NoProfile -File "$Ab\media\media.ps1" -Action verify -RunPath $Run
```

- `snapshot-log`: делает копию `.log` до 32 МиБ в `RUN_.../logs`, проверяет SHA-256, обнаруживает **признаки** путей профиля, email, IP и токенов. Это не автоматическая очистка. Перед любой ручной публикацией лог обязательно просмотреть и удалить личные данные.
- `index-video`: **не копирует** исходный MP4/MKV/WebM/MOV; регистрирует локальный путь и SHA-256. Декодирования, нарезки, синхронизации и подтверждения содержания видео пока нет. Внешний путь остаётся только в локальном `media.json`.
- `status` / `verify`: показывает счётчики и результат перепроверки хешей. При отсутствии/изменении файла нужно отдельно исправить доказательства, не выдавая игре `PASS`.
- Повторный импорт идентичного файла в ту же сцену и сторону регистрирует `SKIPPED_DUPLICATE`. Привязка файлов к сцене считается **непроверенной** даже при правильном SHA-256.

Отчёт содержит только числа зарегистрированных логов/видео и число ожидающих проверки приватности; содержание, внешние пути и сам `media.json` в ZIP не включаются. Даже после сохранения лога сцена `G00.W-05.BASELINE.OVERVIEW` сохраняет статус `PENDING_OTHER_MEDIA`, пока не проведена настоящая проверка клиента и условий запуска.

ZIP возвращает `path` и SHA-256. В пакет попадают только отчёт и зарегистрированные PNG; исходные `latest.log`, другие файлы игрового каталога, приватные заметки и записи видео **автоматически не включаются**.

```powershell
$Package = 'ВСТАВИТЬ_ПОЛНЫЙ_ПУТЬ_ИЗ_ВЫВОДА_EXPORT'
pwsh -NoProfile -File "$Ab\reporting\report.ps1" -Action verify-archive -ArchivePath $Package
pwsh -NoProfile -File "$Ab\reporting\report.ps1" -Action import -ArchivePath $Package -ImportRoot 'D:\TC6_AB_Imported'
```

Повторный импорт **того же неповреждённого ZIP** возвращает `ALREADY_IMPORTED_VERIFIED`; ничего не перезаписывает. Повреждённый ZIP или конфликтующее содержимое ранее импортированной папки вызывают ошибку.

## Что ещё не готово

- Истинное сопоставление условий G00: версия Java/NeoForge, Git SHA игрового порта, список модов, FOV, гамма, GUI Scale, разрешение, шейдеры и пакеты.
- Автоматический захват видео, анализ и редактирование журналов, FFmpeg-клипы и синхронизация между версиями. Сейчас возможны только локальная копия выбранного лога и индексирование готового видео.
- Подтверждённая человеком подготовка реальных сцен, калибровка камер и визуальный `PASS`.
- Новый код регистрации медиа ещё не прошёл пользовательское тестирование на Windows. Предыдущие пункты `C/R/I` пользователь уже проверил; Overlay работал корректно, а дополнительный разделитель удалён.

Оставьте исходную пользовательскую сессию и каталоги `saves` нетронутыми. Доказательства подготавливаются **вне Git**; никакие большие PNG или видео не публикуются автоматически.
