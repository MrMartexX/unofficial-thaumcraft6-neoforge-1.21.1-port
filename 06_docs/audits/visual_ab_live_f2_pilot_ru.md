# Visual A/B Harness: первый настоящий F2-пилот (Windows 10/11)

**Подготовлено:** 04.11.2026. **Режим:** `CAPTURE_TRANSPORT_SMOKE` (не оценка визуального соответствия).  
**Предварительные условия:** `validate-offline.ps1` полностью PASSED на Windows PowerShell 7.6.9.

## 1. Зачем этот пилот

Подтвердить полный путь от реального Minecraft F2 до независимого каталога доказательств:

1. Контроллер указывает активные сцену и игровую сторону.
2. Пользователь делает **новый** F2 в соответствующем клиенте после активации наблюдения.
3. Контроллер находит файл в правильной папке `screenshots`.
4. PNG копируется **без удаления исходника**.
5. Вычисляется SHA-256; результат записывается в `session.json`.
6. После второй игровой версии `verify` показывает 2 корректных файла и 0 повреждённых.
7. Никакого автоматического `PASS` игровой визуальной точности.

## 2. Выбор карты и миров

Использовать существующую согласованную пару:

- LEGACY: `TC6_PARITY_FLAT_1_12_2_RESET_20261103_213123_465257`.
- MODERN: `TC6_PARITY_FLAT_1_21_1_RESET_20261103_213123_465257`.

**Для технического F2-теста**, а не для закрытия исходной находки, выбрать существующую карточку `G00.W-05.BASELINE.OVERVIEW`.

Это карточка регистрации ресурсов/запуска, а не полноценная готовая визуальная сцена. Она требует логов и имеет 0 обязательных F2 в исходном каталоге. Два дополнительных F2 проверяют **транспорт и привязку**; они не меняют `W-05` на `PASS` и не доказывают полноту G00.

Не создавать новые миры и не нажимать Restore clean test worlds.

## 3. Перед первым запуском

1. Убедиться, что оба Minecraft закрыты.
2. Сохранить работу в основном исходном репозитории. **Не переключать его ветку только ради Harness**.
3. Зафиксировать отдельно действительный SHA оригинального репозитория порта командой `git -C D:\Thaumcraft_6_port_to_1.21.1 rev-parse HEAD`. Это лишь SHA исходного дерева, не доказательство тождественности конкретного собранного JAR.
4. Запускать оригинал штатным профилем Forge 1.12.2/Java 8, порт штатным `run-client.bat`/Java 21. Не открывать сохранение одной версии другой версией.
5. Проверить в Harness, что `tools/reports/local/visual-ab/config.local.json` по-прежнему указывает на игровые каталоги оригинала и порта.
6. Выбрать каталог результатов с достаточным свободным местом, например `D:\TC6_AB_Evidence`. Путь примерный и не создаётся до команды Start.

Не требуется запускать повторные проверки всех 48 карточек; офлайн-пакет уже пройден.

## 4. Создание тестовой сессии

В отдельном окне PowerShell 7:

```powershell
pwsh -NoProfile -File D:\TC6_AB_Cycle1\tools\visual-ab\session\controller.ps1
```

В меню:

- Выбрать `1` (создать сессию).
- Указать каталог результатов `D:\TC6_AB_Evidence` либо свой внешний каталог.
- Идентификатор пары миров: `RESET_20261103_213123_465257`.
- Записать показанный полный путь `RUN_...`: он понадобится для продолжения после сбоя.

Не выставлять вручную игровой результат `PASS`: меню этого и не делает.

## 5. Оригинал 1.12.2

1. В меню выбрать `4` (выбрать сцену и сторону).
2. Ввести `G00.W-05.BASELINE.OVERVIEW`.
3. Ввести сторону `legacy`.
4. Запустить оригинал и открыть выбранный LEGACY RESET-мир.
5. Для стабильного вида при подтверждённой функции выполнить `/function tc_parity:home` (ожидаемо X=0.5, Y=64, Z=-12.5; yaw/pitch 0/0). При отсутствии функции зафиксировать ошибку и не выдумывать заменяющие команды.
6. Вернуться в окно контроллера, выбрать `5`, попросить **1 новый F2**.
7. Дождаться строки `Watching for NEW F2 PNGs`.
8. Переключиться в Minecraft, нажать **F2 один раз**.
9. Вернуться к контроллеру и дождаться `CAPTURE_LIMIT_REACHED` или `WATCH_TIMEOUT`. При успешной регистрации увидеть запись `CAPTURED`.
10. После подтверждения можно закрыть оригинальный клиент обычным способом.

**Важно:** если F2 сделан *до* запуска наблюдения, контроллер намеренно игнорирует его как старый файл. В таком случае повторить F2 после Watch или использовать ручной импорт. Исходные PNG удалять не нужно.

## 6. Порт 1.21.1

Повторить тот же процесс:

1. В меню `4`: тот же SceneId.
2. Сторона `modern`.
3. Запустить порт из его обычной среды разработки и открыть согласованный MODERN RESET-мир.
4. При подтверждённой функции выполнить `/function tc_parity:home`.
5. В меню `5`: ожидать 1 новый F2, затем нажать F2 в Minecraft.
6. Дождаться `CAPTURED`. Не переключать сторону в контроллере во время активного Watch.
7. Закрыть клиент после подтверждения.

Не запускать `tc_parity:build`, `tc_parity:unlock`, не перестраивать стенды и не выполнять тесты расходования предметов. В этом пилоте достаточно одного неизменённого ракурса.

## 7. Проверка результата

В контроллере:

- `S`: должно быть 2 зарегистрированных PNG.
- `9`: должно быть `valid=2`, `invalid=0`.
- `8` (полнота) может сообщать `IMAGE_COUNTS_MET_OTHER_MEDIA_PENDING`, поскольку исходная G00-карточка требует логов. Это **нормально**: клиентский визуальный PASS по карточке не ставится.
- `0`: безопасно выйти; `session.json` останется сохранённым.

Если клиент упал после одного скриншота, просто открой контроллер повторно и выбери `2` с предыдущим `RUN_...` (без создания новой сессии).

## 8. Что передать для анализа

Достаточно:

1. Строк `CAPTURED` из LEGACY и MODERN.
2. Вывода `S` и `9`.
3. Полного пути `RUN_...` (без загрузки больших архивов).
4. Отдельного SHA исходного репозитория порта.
5. Любой ошибки запуска игры/функции `home` либо несовпадения камеры.
