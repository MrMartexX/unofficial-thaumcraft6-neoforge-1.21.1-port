Findings:

- **3 of 17** have the same exact registered item path in the port: `curiosity_band`, `cloud_ring` and `golem`. These are name-only correspondences.
- **7 of 17** have credible split-item candidates. Original 1.12 `ItemTCBase` metadata or NBT must be compared against current separate item IDs. For example, `curio` has seven metadata variants and seven name-compatible port IDs. `crystal_essence` is NBT-sensitive, and the modern registry has **37** `crystal_essence_*` IDs; do not interpret that as 37 proven equivalents.
- **3 of 17** have plausible renames: `label` → `jar_label` family, `sanity_soap` → `sane_soap`, and `amulet_vis` → `vis_amulet`. Each needs class/semantic review.
- **4 of 17** currently have no established item counterpart: `celestial_notes`, `verdant_charm`, `voidseer_charm` and `creative_flux_sponge`. Similar thematic names such as `voidseer_pearl` or `verdant_heart` are **not evidence** of equivalent objects.
- `ItemSealPlacer` is registered originally as `seal` with subtype `blank`, and expands metadata variants from SealHandler types; the current separate seal IDs cannot be verified with a name-only audit. `enchanted_placeholder_*` may be placeholders, not full legacy implementation.

2. Inspect original and port classes and the active resource/model paths for each **unresolved** or **renamed** item/block; link exact modern source lines and record behavior equivalence or documented intentional change.

4. Run the source inventory PowerShell script **only when present in a checked-out/isolated PR #11 worktree**. It is not currently present on the user's local default branch; a `pwsh -File` file-not-found message therefore does not validate or invalidate the script.
5. Perform bundled validation (script consistency, resources, registries, dedicated server and client screenshots/animation checks) before advancing the gate. Automated registry checks alone are not a visual-parity result.
