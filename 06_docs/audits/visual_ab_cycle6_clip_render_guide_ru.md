# Thaumcraft Visual A/B Harness — Cycle 6: безопасная нарезка клипов

Дата: 05.11.2026. Статус: подготовлен код и единый синтетический offline gate; **реальное исполнение ffmpeg на пользовательских видео не выполнялось**.

Основа: Cycle 5 (`4ac84bfb`). Пользователь подтвердил полный Windows offline PASS Cycle 5; в этих проверках нет ни декодирования видео, ни подтверждения визуального совпадения игры.

## Зачем нужен этап

`ffprobe` уже позволяет проверить контейнер и допустимые временные границы. Cycle 6 добавляет **отдельный явный запуск** `ffmpeg` для двух записей одной сцены. Видео перекодируются в новые файлы MP4 для последующего ручного просмотра и сравнения. Перекодирование с `libx264` **не сохраняет исходные пиксели побитово** и не служит доказательством игрового паритета.

## Ограничения безопасности

1. Допустима только зарегистрированная пара `legacy`/`modern` в одном RUN, для одной сцены, с действительными ID плана, ffprobe-метаданных и предпросмотра.
2. Команды из `video-previews.json` не исполняются напрямую. Аргументы **перестраиваются заново** из зарегистрированных источников и плана и сравниваются с сохранённым предпросмотром. Подмена `-n`, `-i`, времён или выходного пути прерывает нарезку.
3. SHA-256 каждого исходника проверяется **до и после** работы ffmpeg; выход создаётся только в новой папке `RUN/clips/VPLAN_.../VPREV_...`.
4. Есть `-nostdin`, `-n` (отказ от перезаписи) и ограничение выполнения **10 минут на каждый клип**. Встроенного автоматического удаления клипов нет. При сбое частичные результаты сохраняются под новым ID, повторно использовать тот же PreviewId нельзя: создаётся новый preview.
5. Проверяется отсутствие точек повторной обработки/ссылок у выходных каталогов и у самого файла-источника. Предварительно сгенерированные клипы нельзя использовать как «первичные» источники для этой операции.
6. `video-renders.json` сохраняется **локально** в RUN, а клипы и их локальные пути **не включаются** в экспортный ZIP. Отчёт публикует только число успешно закодированных пар; всё остаётся `ENCODED_UNREVIEWED`, `NOT_VERIFIED`, `NOT_RUN`.

## Реальная нарезка — отдельный поздний пилот

Нужны два настоящих видео из клиентов 1.12.2 и 1.21.1, зарегистрированные через меню `V`; план `T`, затем `B` для `inspect` и `preview`. Пока видео нет, этот раздел пропускаем.

В новой версии контроллера:

- `F` → Enter: показать количество успешно закодированных пар.
- `F` → `V`: проверить SHA-256 источников и созданных клипов.
- `F` → `R`: указать конкретный `PreviewId`, внимательно проверить предупреждение, ввести `RENDER` для фактического запуска ffmpeg. Enter отменяет операцию.

Прямой вызов после готового предпросмотра:

```powershell
$Run = 'D:\TC6_AB_Evidence\RUN_20261104T202107Z_5153ed72'
$Ab = 'D:\TC6_AB_Cycle1\tools\visual-ab'
$Preview = 'VPREV_ЗАМЕНИТЬ_НА_РЕАЛЬНЫЙ_ID'

# ВНИМАНИЕ: следующий вызов действительно запускает ffmpeg для двух видео.
pwsh -NoProfile -File "$Ab\video\render.ps1" -Action render -RunPath $Run -PreviewId $Preview

# После нарезки; только контроль целостности, не визуальная оценка:
pwsh -NoProfile -File "$Ab\video\render.ps1" -Action verify -RunPath $Run
```

Если FFmpeg не доступен в PATH, укажи `-FfmpegPath 'D:\tools\ffmpeg\bin\ffmpeg.exe'`. Реальные видео до согласованного пилота не требуются. Вывод ffmpeg после преобразования надо вручную проверить на кадры, точность длительности, соответствие камеры, анимации, отсутствие случайных расхождений. Даже успешная нарезка не означает `PASS`.
