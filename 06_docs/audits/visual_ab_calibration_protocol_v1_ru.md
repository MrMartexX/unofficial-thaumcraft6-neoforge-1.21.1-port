# Visual A/B Harness G00: протокол калибровки v1.0

Дата: 04.11.2026. Статус: **GUIDED / NOT CLIENT VERIFIED**.

## Назначение

Этот протокол используется до игровых A/B-захватов. Он не изменяет настройки, сохранения, JAR или код. Наличие `SOURCE_CATALOG_VALID` и `doctor.errors=0` **не** означает `CLIENT_VERIFIED`.

## Исходное наблюдение Environment Doctor

| Параметр | Оригинал (1.12.2) | Порт (1.21.1) | Требуемое действие |
| --- | ---: | ---: | --- |
| gamma, исходное значение | 0.0 | 0.5035211267605634 | Выставить сопоставимую яркость *в интерфейсе*, проверить визуально; сырые шкалы могут различаться |
| guiScale, исходное значение | 3 | 4 | Согласовать **реальные пиксельные размеры** GUI, а не просто числа |
| renderDistance | 12 | 32 | 12 чанков в обоих клиентах |
| maxFps | 120 | 260 | Для динамических тестов выбрать одинаковый разумный лимит, например 120 FPS |

Значения получены из файлов `options.txt` и требуют проверки непосредственно в игре. Не переносить `options.txt` между версиями Minecraft.

## Шаг 0. Предварительная безопасность

1. Убедиться, что каталог оригинальной игры открыт только Minecraft 1.12.2, современный только 1.21.1.
2. Использовать существующие подготовленные миры (или согласованную пару RESET с одинаковой временной меткой); **не запускать восстановление миров только для калибровки**.
3. Убедиться, что Modern использует именно тестируемый коммит. Исследовательский baseline 72eaac17... не заменяет runtime Git SHA.
4. Для видео/снимков заранее выбрать единый режим записи, разрешение экрана и формат сохранения.
5. Не запускать `/function tc_parity:build`; он перестраивает площадки. `/function tc_parity:home` применять только если функция существует в выбранном мире.

## Шаг 1. Согласовать базовый профиль

Установить отдельно в каждом клиенте:

- Оконный режим, целевой размер клиентского изображения 1280×720 (проверять фактический размер итогового F2 PNG).
- FOV: отображаемое значение 70. Значение `fov:0.0` в `options.txt` не заменяет проверки интерфейса.
- Render Distance: 12 чанков.
- Particles: All / Все.
- Яркость: сопоставимый режим; начать с минимальной/одинаковой номинальной яркости, далее фиксировать наблюдаемую разницу.
- Режим графики, mipmap, VSync и ограничения FPS: зафиксировать выбранные значения для каждой версии; если опции неэквивалентны, записать это.
- Не включать новые шейдеры, OptiFine/ресурс-паки в одном клиенте без такого же контролируемого условия для второго.
- Simulation Distance (1.21.1): записать отдельно, **не считать** напрямую эквивалентом опций 1.12.2.
- GUI Scale: подобрать по размерам элементов в пикселях; записать сырые значения отдельно.

Нельзя автоматически считать оттенок и экспозицию рендеров идентичными только потому, что ползунки совпали.

## Шаг 2. Проверка симметрии камеры

1. В каждом клиенте открыть соответствующий плоский мир.
2. Если подтверждена функция, выполнить `/function tc_parity:home` (ожидаемая позиция 0.5, 64, -12.5; yaw/pitch 0/0).
3. Проверить по F3 точные X/Y/Z, yaw/pitch, режим камеры, направление взгляда.
4. Сверить игровое время, погоду, освещение, предметы в руках и статус GUI.
5. Зафиксировать, что наземная площадка находится на Y=63 в **обеих** версиях.
6. Сделать по одному контрольному F2-снимку. Не использовать обрезку/масштабирование как замену одинаковой внутриигровой камеры.

## Шаг 3. Заполнить G00-карточку

Записывать отдельно для каждой версии:

- Minecraft, загрузчик, Java, перечень модов и ресурс-паков.
- Игровой каталог/идентификатор профиля и `runtimeTargetSha` для порта.
- Имя и тип мира (PRIMARY/RESET, одинаковая RESET-метка).
- Разрешение F2 PNG; оконный/полноэкранный режим.
- FOV, координаты, yaw/pitch, калибровку GUI Scale и gamma.
- Render/Simulation Distance, графика, частицы, VSync/FPS, mipmaps.
- Возникшие проблемы при загрузке/перезагрузке ресурсов.
- Файлы контрольных скриншотов, SHA-256 и логи после очистки потенциально личных данных.

Временно сохранять файлы в локальном каталоге вне Git; автоматическая регистрация доказательств появится в Cycle 2.

## Решение о допуске к A/B

- `CALIBRATED`: обе стороны проверены в клиенте, критические параметры согласованы либо документировано и принято их несовпадение.
- `CALIBRATION_REQUIRED`: обнаружены несовпадения, мешающие надёжному сравнению.
- `BLOCKED`: мир, версия, мод или камера недоступны.

**Не ставить игровой `PASS`** при прохождении G00: калибровка подтверждает только условия съёмки, а не соответствие игровых механик.

## Последующие сценарии

Оригинал и порт проводить крупными пакетами A/B. Сначала полностью снять эталон оригинала при зафиксированном профиле, затем порт с теми же сценами. Для случайных/динамических FX записывать видео и серии повторов; одинаковый world seed не гарантирует одинаковую последовательность частиц.
