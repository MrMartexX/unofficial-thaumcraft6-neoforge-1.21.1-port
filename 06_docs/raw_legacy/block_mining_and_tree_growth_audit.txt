High priority checks
============================================================

Leaves disappearing after generated trees

Likely causes to verify:
1. Generated leaves are placed with LeavesBlock.DISTANCE = 7 and remain too far from recognized logs.
2. Thaumcraft logs may not be loaded into minecraft:logs tag at runtime.
3. Stabilization scan radius or Y range may not cover all generated Greatwood leaf nodes.
4. Generator may create leaves farther than modern vanilla leaf-distance rules allow, while legacy leaf decay used older logic.
5. Branch or log generation may differ from legacy, leaving some side leaf clusters unsupported.

If only a few outer leaves disappear, this may be modern distance behavior or branch mismatch.
If many leaves disappear, logs tag or distance recalculation is probably wrong.

Legacy leaf drops to verify:
- Greatwood leaves sapling chance base should be 1/75.
- Silverwood leaves sapling chance base should be 1/75.
- Silverwood leaves had special quicksilver nugget behavior through apple-drop logic.
- Shears or Silk Touch should drop leaves themselves.

            }
        }

    private static Block registerBlock(Block block, ItemBlock itemBlock) {
        ForgeRegistries.BLOCKS.register(block);
        itemBlock.setRegistryName(block.getRegistryName());
        ForgeRegistries.ITEMS.register(itemBlock);
        Thaumcraft.proxy.registerModel(itemBlock);
        return block;
    }
    
    private static Block registerBlock(Block block, Class clazz) {
        ForgeRegistries.BLOCKS.register(block);
        try {
            ItemBlock itemBlock = (ItemBlock)clazz.getConstructors()[0].newInstance(block);
            itemBlock.setRegistryName(block.getRegistryName());
            ForgeRegistries.ITEMS.register(itemBlock);
            Thaumcraft.proxy.registerModel(itemBlock);
        }
        catch (Exception e) {
            e.printStackTrace();
        }
        return block;
    }

============================================================
Manual comparison checklist
============================================================

Sapling behavior
- Stage property exists and defaults to 0.
- Random tick checks brightness above sapling >= 9.
- Random tick chance is 1/7.
- First growth changes stage 0 to 1.
- Second growth attempts generation.
- Bonemeal success chance is 25%.
- Greatwood requires 2x2 saplings.
- Silverwood grows from one sapling.
- Failed generation restores the sapling or 2x2 saplings.

Silverwood generator
- Height formula matches legacy.
- Clearance check matches legacy.
- Soil check matches legacy or acceptable 1.21 equivalent.
- Crown formula and radius match legacy.
- Cross trunk shape matches legacy.
- Root or diagonal log placement matches legacy.
- Shimmerleaf patch only appears in worldgen mode, not sapling mode.
- Modern leaves distance does not remove valid legacy leaves.

Greatwood generator
- heightAttenuation, branchSlope, scaleWidth, leafDensity match legacy.
- heightLimitLimit and leafDistanceLimit match legacy.
- leaf node generation matches legacy.
- leaf blob radius and layers match legacy.
- branch base generation matches legacy.
- 2x2 trunk generation matches legacy.
- second upper tree pass matches legacy.
- spider dungeon is not used for sapling mode.
- Modern leaves distance does not remove valid legacy leaves.

Block mining and data
- Logs: axe, hardness 2.0, resistance 5.0, Silverwood light 5.
- Planks/stairs/slabs: axe and correct hardness/resistance.
- Ancient/arcane/eldritch/amber stone-like blocks: pickaxe and correct hardness/resistance.
- Leaves: hoe tag, shears/silk drops leaves, otherwise sapling chance.
- Plants: simple self-drop unless legacy says otherwise.
- Ores: check if current self-drop is temporary, legacy may need item drops later.
